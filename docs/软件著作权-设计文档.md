# 系统服务导航门户设计文档

## 1. 文档概述

本文档用于说明“系统服务导航门户”的总体设计、功能结构、数据结构、接口设计、安全设计和部署设计，可作为软件著作权申报中的系统设计说明材料。

## 2. 软件基本信息

| 项目 | 内容 |
| --- | --- |
| 软件名称 | 系统服务导航门户 |
| 软件版本 | V1.0 |
| 软件类型 | Web 应用软件 |
| 运行环境 | Linux/Windows，Python 或 Node.js 运行环境，现代浏览器 |
| 服务对象 | 单位内部用户、系统管理员、信息化管理人员 |
| 主要用途 | 提供内部业务系统统一入口，并支持管理员维护入口配置 |

## 3. 设计背景

单位内部常存在多个业务系统、办公系统、数据平台和管理工具。用户在日常工作中需要记忆不同系统地址，管理员也需要维护入口、状态、说明和图片等展示信息。系统服务导航门户通过统一入口页面和可视化后台管理功能，解决系统入口分散、维护不便、访问效率低等问题。

## 4. 设计目标

1. 为内部用户提供统一、清晰、可搜索的系统访问入口。
2. 为管理员提供简单的入口维护后台，支持新增、编辑、删除、排序和图片上传。
3. 通过配置文件驱动页面内容，降低维护成本。
4. 不依赖数据库和大型框架，便于在内网服务器快速部署。
5. 提供登录认证、路径校验、上传类型限制和配置备份等基础安全能力。

## 5. 总体架构设计

系统采用轻量级 Web 架构，由浏览器端页面、后端 HTTP 服务和本地配置文件组成。

```text
浏览器用户
  ├─ 前台门户页面 index.html / starbucks.html
  │   └─ assets/app.js 读取 assets/config.json 并渲染入口目录
  │
  └─ 管理后台页面 admin.html
      └─ assets/admin.js 调用 /api/* 接口维护配置

后端服务
  ├─ server.py：生产环境可用的 Python 服务实现
  └─ server.js：Node.js 服务实现，便于本地开发与测试

数据与资源
  ├─ assets/config.json：系统入口、分类、组织信息配置
  ├─ assets/uploads/：后台上传图片
  └─ data/backups/：配置修改自动备份
```

## 7. 功能模块设计

### 7.1 前台门户模块

前台门户面向普通用户，核心功能包括：

1. 组织信息展示：显示单位名称、门户名称、说明文字和支持部门。
2. 系统入口展示：按卡片形式展示系统名称、描述、分类、状态、标签、图片和跳转地址。
3. 分类筛选：按“常用系统”“业务办理”“数据查询”“管理工具”等分类筛选。
4. 关键词搜索：支持按系统名称、描述、状态、分类名称和标签搜索。
5. 状态提示：根据系统状态显示“可访问”“待配置”“维护中”等状态标识。
6. 外部跳转：可访问卡片以新窗口方式打开，避免覆盖门户页面。
7. 空状态提示：无匹配结果时显示友好提示并提供重置筛选操作。

### 7.2 管理后台模块

管理后台面向管理员，核心功能包括：

1. 登录认证：通过管理员密码登录，登录成功后写入 HTTP Only Cookie。
2. 会话检查：进入后台时自动检查当前会话是否有效。
3. 入口列表：展示当前全部系统入口，支持名称、描述、分类、标签搜索。
4. 新增入口：录入系统名称、描述、分类、图标、图片、地址、状态和标签。
5. 编辑入口：选择已有卡片后修改字段并保存。
6. 删除入口：删除指定系统入口，并同步更新配置文件。
7. 排序调整：对入口卡片执行上移、下移，控制前台展示顺序。
8. 图片上传：上传 jpg、png、webp、gif 格式图片并关联到入口卡片。
9. 图片删除：删除已上传图片并清空卡片图片字段。
10. 实时预览：编辑过程中展示接近前台效果的卡片预览。
11. 保存反馈：保存成功后显示弹窗提示，明确配置已生效。

### 7.3 配置管理模块

系统入口数据统一保存在 `assets/config.json` 中。后台所有新增、修改、删除、排序操作最终都会写入该文件。配置写入前，系统会在 `data/backups/` 目录生成备份，便于误操作后恢复。

### 7.4 静态资源服务模块

后端服务负责提供 HTML、JavaScript、CSS、图片和 JSON 等静态资源访问。访问路径经过规范化处理，避免目录穿越风险。

## 9. 接口设计

| 接口 | 方法 | 说明 | 权限 |
| --- | --- | --- | --- |
| `/api/session` | GET | 查询当前会话状态 | 公开 |
| `/api/login` | POST | 管理员登录 | 公开 |
| `/api/logout` | POST | 管理员退出登录 | 登录后 |
| `/api/config` | GET | 获取完整配置 | 登录后 |
| `/api/config` | PUT | 调整系统入口排序 | 登录后 |
| `/api/systems` | POST | 新增系统入口 | 登录后 |
| `/api/systems/:id` | PUT | 修改系统入口 | 登录后 |
| `/api/systems/:id` | DELETE | 删除系统入口 | 登录后 |
| `/api/upload` | POST | 上传入口图片 | 登录后 |
| `/api/upload` | DELETE | 删除已上传图片 | 登录后 |

## 10. 安全设计

1. 管理后台接口统一要求登录认证。
2. 管理员密码通过 `ADMIN_PASSWORD` 环境变量配置，不写入代码仓库。
3. 登录成功后使用 HTTP Only Cookie 保存会话标识，降低脚本读取风险。
4. Cookie 设置 `SameSite=Strict`，减少跨站请求风险。
5. 请求体大小设置上限，避免超大请求占用资源。
6. 上传文件限制为常见图片格式。
7. 图片删除路径必须匹配 `assets/uploads/` 下的安全格式。
8. 静态文件访问采用路径规范化和根目录校验，避免目录穿越。
9. 写入配置前自动备份，降低误操作造成的数据损失。

## 11. 部署设计

系统可部署在内网 Linux 服务器，推荐目录为 `/var/www/service-portal`。生产环境可使用 `server.py`，适配常见 Linux 自带 Python 运行环境，也可使用 Node.js 版本 `server.js`。

启动参数包括：

| 参数 | 说明 |
| --- | --- |
| PORT | 服务监听端口，默认 80 |
| ADMIN_PASSWORD | 管理员登录密码 |

部署方式支持 systemd 托管，实现开机自启和异常重启。

## 12. 异常处理设计

1. 配置文件读取失败时，前台显示配置加载失败提示。
2. 未登录访问后台接口时，返回 401 状态。
3. 登录密码错误时，返回明确错误信息。
4. 新增或编辑入口缺少必填字段时，返回 400 状态。
5. 删除不存在的入口时，返回 404 状态。
6. 上传文件类型不符合要求时，返回错误提示。
7. 后端未知异常返回 JSON 格式错误，方便前端展示。

## 13. 可维护性设计

1. 前台门户、管理后台、后端服务和配置数据分离，便于单独维护。
2. 入口内容配置化，新增系统无需修改 HTML。
3. 前端采用独立脚本文件组织，页面只负责挂载根节点。
4. 后端核心逻辑按认证、配置、上传、静态服务分层。
5. 配置文件使用 JSON 格式，便于人工查看和备份。
6. 测试文件覆盖核心文件存在性、前台渲染特征、后台接口和上传功能。

## 14. 后续扩展设计

系统后续可扩展以下能力：

1. 多管理员账号与角色权限。
2. 登录失败次数限制与操作审计日志。
3. 系统入口访问统计与常用入口推荐。
4. 配置导入、导出和一键回滚。
5. 与 LDAP、AD 或统一身份认证平台集成。
6. 按部门、岗位或权限展示不同入口。

## 15. 设计结论

系统服务导航门户采用轻量级、配置驱动的 Web 架构，在较低部署和维护成本下实现了内部系统统一入口、后台配置管理、图片上传、配置备份和基础安全控制。系统结构清晰，功能边界明确，适用于单位内网环境下的系统入口集中管理场景。
